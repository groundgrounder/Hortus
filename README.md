Hortus is a native Markdown knowledge viewer that keeps large Mermaid trees readable and refreshes your notes as agents write them.

[![Download for macOS · Apple Silicon](docs/images/download-macos.svg)](https://github.com/groundgrounder/Hortus/releases)

## Why Hortus

- **Large diagrams stay readable.** Trees that outgrow the note width flow into columns while keeping their text at a readable size. The comparison above uses the same 81-node source at 700 px per panel.
- **A native Mac app.** Native text and drawing, with no WebView or Electron. No runtime networking or telemetry.
- **Read first, write with an agent.** Read your knowledge vault while an agent works on its Markdown files in a terminal. External changes refresh in place; press ⌘E when you want to edit a note yourself.
- **Your notes are ordinary files.** Open a Markdown folder directly, including an existing Obsidian vault. Wiki links, embeds, tasks, callouts and frontmatter are supported; application state stays outside the note folder. LaTeX math, inline $…$ and display $$…$$, renders natively in the reading view.

Try the original [CC0 demo vault](fixtures/demo-vault/README.md). On an Apple M3 MacBook Air (macOS 27.2), Hortus 0.1.4 takes 15.3 MiB on disk, shows the note about 0.5 s after launch, and uses about 150 MiB of memory with the demo diagram open, as one process. Each figure is the median of five runs; see `tools/compare-obsidian.py` for the method.

## Install

Requires **macOS 27 or later and an Apple Silicon Mac**. Version 0.1.4 uses ad-hoc signing and is not notarized.

1. Download `Hortus-0.1.4-arm64.dmg` from [Releases](https://github.com/groundgrounder/Hortus/releases), open it, and drag Hortus into Applications.
2. Open Hortus. macOS may block the first launch because it cannot verify the developer. Choose either of the following ways to allow this copy:

**System Settings:** After the blocked attempt, click **Done**, open **System Settings → Privacy & Security**, find the message about Hortus, and click **Open Anyway**. Follow the confirmation and authentication prompts, then launch Hortus again if needed.

**Terminal:** After copying the app into Applications, run:

```sh
xattr -dr com.apple.quarantine /Applications/Hortus.app
open /Applications/Hortus.app
```

Both ways were tested on macOS 27.2. The wording of the system prompt may differ on other macOS versions.

## Continuous integration

CI runs on pull requests, pushes to `main`, and manual dispatches. Ubuntu 24.04 checks Rust formatting, Clippy, workspace tests, and math-check tests. GitHub's public-preview `xcode-27` image builds the macOS app with warnings treated as errors, runs the Swift tests, and checks the public tree and app bundle. Its documented image has macOS 27.0.1, Xcode 27.1, and Swift 6.4.

CI does not create release packages, notarize, publish, or replace local release, real-window, TCC, or performance validation. Job logs remain available in each Actions run.

## Known issues

- The 0.1.4 download is ad-hoc signed. A replacement download or update may require first-launch approval again.
- When the terminal accesses protected folders such as Documents, macOS may request permission. App updates may require you to grant access again in **Privacy & Security → Files & Folders**.
- Mermaid support includes mindmaps and flowcharts with branches, merges, loops, and top-level subgraphs. Unsupported diagram types remain visible as source.
